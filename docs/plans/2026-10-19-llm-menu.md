# Strata／Splash SwiftBarメニュー Implementation Plan

## Requirements

設計根拠: [dig log](../dig/2026-10-19-splash-plugin.md) と本セッションのQ21への回答「a」。**設計・実装計画とも承認済み**（計画提示後のユーザー回答「ok」）。dig logのQ21「承認待ち」は回答前の記録であり、本計画で承認を反映する。

- このリポジトリはLLM以外も追加できるSwiftBarプラグイン集。今回、StrataとSplashを1つのアイコン・メニューから操作するプラグインを追加する。共通プラグインフレームワークは作らない。
- Strata Menubarのコード・設定は変更しない。SwiftBar利用時には同アプリを終了している前提で、同期・連携はしない。
- 各エンジン内は1サーバー。StrataとSplashは独立し、同時稼働を制限・警告・自動切り替えしない。
- Startは明示操作のみ。Stopは毎回確認。稼働中のモデル変更は中断を説明して確認後、停止・再起動する。キャンセル時は選択も稼働状態も変更しない。停止失敗時は次を起動しない。
- SwiftBarを終了してもサーバーは継続し、再起動後も自己起動した同一サーバーを管理できる。OSログイン時・サーバー異常終了時の自動起動／再起動はしない。エンジン自身の復旧・アイドル解放の仕様は変更しない。
- 外部起動サーバーは監視のみ。停止・取り込み・モデル切り替えはしない。初期検証時に親Herdrペインで稼働しているSplashも外部扱いとし、勝手に停止しない。
- `~/.config/swiftbar-plugins/llm.json` にユーザー設定を置く。具体的なモデル・個人のパスは実装や追跡する設定例に入れない。
- Strataは表示名と準備済みのモデル設定JSONを登録し、そのJSONを直接使用する。expert cache等の上書き、モデル取得・初回準備・削除は扱わない。
- Splashは表示名・モデルID・CLI引数配列`args`を登録する。任意の共通`modelCacheDir`を`HF_HUB_CACHE`に渡す。省略時は保存先を上書きせず、既存ファイルの移動もしない。
- Splashの通常Start・モデル切り替えは`--offline`。別操作「ダウンロード／更新して起動」は確認後にオンライン起動する。独自ダウンローダーは作らずSplashに委ねる。失敗時に自動でオンライン起動へ切り替えない。
- 両エンジンとも`127.0.0.1`限定。ポートは個別設定、既定はStrata 8080、Splash 8000。両方に同じポートを設定した場合は設定エラー。
- UIの固定テキスト（メニュー・確認ダイアログ・検証エラー・依存不足の案内）は英語。ユーザー指定のモデル表示名は翻訳しない（実装後のユーザー追加依頼）。
- 常時表示はアイコンのみ。形・マークで状態を区別し、色だけに依存しない。開いたメニューで各状態・モデル・接続先、操作、チャット／ログ／設定への導線、生成速度・エンジン単体のメモリ・コンテキスト上限を表示する。
- 状態は5秒ごとに更新。生成速度は現在の観測窓に基づく値で、累積平均を現在速度として表示しない。取得不能・非生成時は`—`。
- メモリは**ネイティブ推論エンジン単体の、アクティビティモニタの「メモリ」列に相当するphysical footprint**。Python APIサーバー等は合算せず、Metal割り当て量・RSS・システム全体RAMで代用しない。取得不能時は`—`。

## Implementation Decisions

### 構成と実行環境

- `plugins/llm.5s.sh`をSwiftBarの入口にする。表示とクリック操作を同じ入口で受け、補助コードは`plugins/`外の`scripts/llm/`に置く。SwiftBarはプラグインフォルダを再帰探索するため、補助ファイルをそこへ置かない。
- Python 3.12以上の標準ライブラリを使用する。JSON・HTTP・ファイルロック・プロセス・Unix socket・macOS API呼び出しを扱い、外部PythonパッケージやSwiftのビルド工程は追加しない。
- 入口は`uv`をPATHとHomebrewの既知の配置から探し、`uv run --offline --no-project --no-python-downloads --python '>=3.12'`で補助処理を起動する。必要なPythonは導入時に準備し、定期更新中のインストールやネットワーク取得はしない。workerは解決済みの`sys.executable`で起動する。
- 入口は作業ディレクトリに依存せずリポジトリ位置を解決する。SwiftBarが起動した際のPATHとターミナルのPATHは同じと仮定しない。依存不足でもエラーアイコンと案内を返す。
- 処理を設定読込、エンジン別起動・HTTP監視、プロセス管理、macOS計測、メニュー描画に分ける。初期実装はこのプラグイン内に閉じ、他プラグイン向けの汎用APIを先回りして作らない。
- 新規文書・コメントは日本語。コメントは理由だけを書く。

### 設定とローカル状態

設定スキーマの骨格（値は説明用であり、これを導入時のモデル初期値として書き込まない）:

```json
{
  "strata": {
    "directory": "/path/to/Strata",
    "port": 8080,
    "models": [{"id": "local-model", "name": "表示名", "config": "/path/to/model.json"}]
  },
  "splash": {
    "executable": "/path/to/splash",
    "port": 8000,
    "modelCacheDir": "/path/to/huggingface/hub",
    "models": [{"id": "local-model", "name": "表示名", "model": "owner/repository:VARIANT", "args": []}]
  }
}
```

- `strata`／`splash`は個別に省略可能。未設定のエンジンは未設定と表示し、一方のモデル・実行環境の不備だけで他方を操作不能にしない。追跡する設定例はモデル一覧を空にし、実パスは含めない。
- モデル`id`はエンジン内で一意な安定キーとし、安全な文字集合に限定する。表示名や配列の位置を状態の識別子にしない。選択モデル、起動中モデルは区別して保存・表示する。未選択時は明示的なモデル選択を案内する。
- `splash.executable`は任意。省略時はPATH／Homebrewから実行可能ファイルを解決する。`strata.directory`からPythonとserver.pyを解決する。パスは絶対パスまたは`~/`を許容し、相対パスは拒否する。
- `args`は文字列配列のままプロセスへ渡し、シェルとして評価しない。管理項目`--model`・`--host`・`--port`・`--offline`、制御を変える`--help`等や`--`区切りの混入を拒否する。`--key=value`形式とSplashが受け付ける省略形も含め、管理値を迂回上書きできないよう検証する。
- 型・空値・重複ID・ポート範囲・NUL・設定構文を検証する。表示名はメニュー制御記号や改行をエスケープし、クリック引数には表示名や生のモデルIDではなく検証済みの内部IDを渡す。
- ユーザー設定はプラグインが書き換えない。編集でモデルが消えたり設定が壊れたりしても、自己起動サーバーのStopとログ参照は起動時の状態から利用可能にする。
- 永続状態は`~/Library/Application Support/swiftbar-plugins/llm/`、プラグインの起動ログは`~/Library/Logs/swiftbar-plugins/llm/`に置く。モデル重み・秘密情報・完全な環境変数・会話本文を状態やリポジトリへ保存しない。ログは起動ごとに上限付きでローテートする。
- 設定例のコピーは手動の初期導入手順とし、既存設定を上書きしない。初回からモデルを自動登録・起動しない。

### サーバーの所有権と操作

安全な永続管理のため、**各稼働サーバーにつき小さなworkerを1つ**だけ置く。これは自動起動サービスではなく、StartからStopまでの所有者であり、自動再起動はしない。

- workerはSwiftBarから切り離した新セッション／プロセスグループのリーダーとなり、対象サーバーを同じグループに子として起動する。stdinは端末から切り離し、stdout/stderrはログへ明示接続する。workerはグループが空になるまで残り、PGIDの再利用を防ぐ。
- 操作はユーザー専用のUnix socket経由でworkerに渡す。socketは短いパスのプライベートな一時ディレクトリに置き、長さ制限を確認する。永続記録に起動ごとのnonce・workerのPID／開始時刻・boot識別・接続先を保持する。応答もnonceと照合する。
- エンジン単位のファイルロックとworker側の直列処理で、連打・定期更新・複数クリックの競合を防ぐ。StrataとSplash間で相互排他は設けない。
- worker自身が現在のグループリーダーであることを検証したうえで停止信号を送る。workerは信号で即終了せず停止処理を継続する。通常はサーバーへSIGTERMで穏当に終了を依頼し、残る同一グループの子孫も終了させる。一定時間で終了しなければ停止失敗として所有権を保ち、再起動を拒否する。暗黙の強制KILLや、保存済みPID／PGIDへの直接killは行わない。
- 正常停止・異常終了とも、workerは残存子孫を確認してから終了を記録する。worker自体が失われた場合、古い記録からプロセスを取り込んで操作し直さない。外部／所有権不明として案内し、新規起動の前に生存・ポートを確認する。
- 所有権はポートやプロセス名から推測しない。HTTPに返されたPIDも停止の根拠にはしない。プロセス調査の権限不足は「不明」であり「終了済み」ではない。
- 起動時のモデル・ポート・実行パスをスナップショットとしてworkerが保持する。設定変更で旧サーバーが見えなくなったり、別ポートへ二重起動したりしない。
- 起動処理は非同期とし、ダウンロード中・モデルロード中でもSwiftBarの更新を塞がない。APIが応答しないだけで自動停止しない。起動中のStopも毎回確認する。
- 確認は固定AppleScriptに引数として文言を渡す`osascript`で実装し、ユーザー値をAppleScript本文に埋め込まない。確認待ちの間は稼働状態・選択を書き換えず、承認後に設定とworker世代を再検証する。モデル変更／オンライン起動に伴う停止は1回の確認にまとめる。
- 停止中のモデル選択は選択保存のみ。稼働中は承認・停止完了後に選択を保存して起動する。起動が失敗したらエラーを残し、以前のモデルを勝手に再起動しない。

### エンジン別の起動契約

**Strata**

- `<directory>/.venv/bin/python <directory>/serve/server.py --engine strata --config <registered-config> --host 127.0.0.1 --port <port>`。作業ディレクトリはStrataのルート。
- 設定JSONは直接参照し、コピー生成・`args`や`env`の上書きはしない。CLIのhost／portは接続管理として明示する。
- JSONの`exe`・`cwd`から期待するネイティブエンジンのパスを解決し、実際の子プロセス識別に使う。構成が曖昧・複数候補の場合はメモリを推測しない。
- 初回準備不足はStrataの既存手段への案内とログで説明し、setupを自動実行しない。エンジンのログは参照JSONの`log`に従うため、プラグインのサーバーログと区別して案内する。
- Strata自身のWeb設定等は元JSONや隣接ファイルへ書く場合がある。プラグイン自身は変更しないが、Strataの通常動作まで読み取り専用になるとは説明しない。

**Splash**

- 公式の`splash serve --model <ID> --host 127.0.0.1 --port <port> ...args`を使う。内部のPythonモジュール起動形式へ依存しない。
- 通常は`--offline`を追加。オンライン操作ではこれを付けず、子の環境に残った`HF_HUB_OFFLINE`／`TRANSFORMERS_OFFLINE`が操作と矛盾しないよう、子に渡す環境だけを整える。モデルキャッシュは指定時だけ上書きする。
- 1.3.2のlauncherは準備後にAPIサーバーへexecする。同じPIDの実行ファイルが変わることを想定し、PythonのAPIサーバーをメモリ計測対象にしない。
- ネイティブエンジンは子孫・実行ファイル・`serve-native`の役割で識別する。内部再起動でPIDが変わったら再解決し、速度の観測基準もリセットする。
- 認証付きAPIへの対応を勝手に無効化しない。認証が必要で監視値を取れなければ「監視不可」と`—`を表示する。認証情報管理機能は今回追加しない。

### 状態取得・メモリ・メニュー

- Strataは`/health`の`service == strata`で識別し、`loaded`と`max_context`を取得する。`/metrics`の`live.state`・`live.tok_s`・`engine.max_context`を利用する。レスポンス中のリクエスト履歴は保存しない。
- Splashは`/status`のスキーマ・instance・ready等を検証する。生成速度は`metrics.decode_output_tokens`と単調時計の差分で求め、インスタンス変更・カウンタ巻き戻り・スリープ後・初回観測では無効化する。累積GPU速度やMetalメモリで代用しない。
- 短いHTTPタイムアウトとレスポンスサイズ上限を設け、失敗を他エンジンの更新へ波及させない。401／タイムアウト／不正JSON／別サービスをStoppedと誤判定しない。リダイレクト先を追って外部ホストへ接続しない。
- API未応答の起動中、サーバー稼働・モデル未ロード、外部稼働、停止失敗、設定不備を区別する。アイドル解放はサーバー停止とは扱わない。
- アイコンの集約はエラー→起動／停止処理中→いずれか稼働→全停止の優先順。詳しい状態はStrata／Splashそれぞれのサブメニューに出す。
- メモリは`ctypes`でlibSystemの`proc_pid_rusage(pid, RUSAGE_INFO_V0, ...)`を呼び、`ri_phys_footprint`の現在値を取得する。V0構造体はApple SDKの宣言どおりに定義し、サイズ96バイト、当該フィールドoffset 72を確認する。`ri_proc_start_abstime`等で対象の同一性を読み取り前後に検証する。
- 自己起動エンジンはworker配下で特定する。外部サーバーは安全に読み取りでエンジンPIDを特定できる場合のみ計測し、曖昧なら`—`。外部PIDの発見は管理権限を与えない。
- 「エンジンメモリ」と表示し、PIDも確認できるようにする。表示単位はGB（10進）とし、実測照合ではraw bytes・表示単位・サンプル時刻を揃える。APIサーバー、ドラフト用別プロセス、vision等を加算しない。
- アクションはSwiftBarの`bash`／`paramN`／`terminal=false`で入口に渡す。メニューの制御記号・引用符・空白を安全に扱う。遅い起動完了をクリック処理で待たない。通知・UI更新から起動を再実行しない。

### 調査済みの根拠と残る検証

- [SwiftBar README](https://github.com/swiftbar/SwiftBar): `.5s.sh`、プラグインフォルダの再帰探索、`sfimage`、`checked`、`bash`・`paramN`・`terminal=false`・`refresh`、実行環境変数。
- [Splash DEVELOPMENT.md](https://github.com/incoai/splash/blob/main/DEVELOPMENT.md): モデルキャッシュ・offline・状態API。導入済み1.3.2の`install/launcher.py:189–274`は準備とexec、`server/runtime.py:510`は子エンジン起動を確認した。
- Strataローカルの`serve/server.py:819`は子エンジン起動、`3646`付近はmetrics、`5337`付近はhealth、`6626`以降は起動引数、`6944`付近はSIGTERMによる終了処理。子エンジンは現行の両実装とも独自sessionを作っていない。
- Apple `/usr/share/man/man1/footprint.1:287–305`: Activity MonitorのMemory列はprocess footprint ledgerを表示する。
- Apple SDK `usr/include/libproc.h:106–111`と`sys/resource.h:184–214`: `proc_pid_rusage`とV0構造体。API権限や実測値の一致はこの計画作成ではまだ試していない。
- SwiftBarは通常のApplications配置には未導入。導入、macOSダイアログ、API／OS計測の実行権限、親プロセス終了後も保持される管理workerは実装時の必須検証。権限不足をsudoやsandbox設定変更で勝手に解決しない。
