## Requirements

Design basis: the [dig log](../dig/2026-10-19-splash-plugin.md) and the answer to Q21 in this session (translated): “a”. **Both the design and implementation plan are approved** (the user's response after the plan was presented, translated: “ok”). The dig log's Q21 “Awaiting approval” entry predates that answer; this plan records the approval.

- This repository is a collection of SwiftBar plugins that may include non-LLM plugins. This work adds a plugin controlling Strata and Splash from one icon and menu. Do not build a shared plugin framework.
- Do not change Strata Menubar's code or configuration. Assume that application is closed when using SwiftBar; do not synchronize or integrate with it.
- One server per engine. Strata and Splash are independent; do not restrict, warn about, or automatically switch their simultaneous operation.
- Start requires an explicit action. Confirm Stop every time. For running-model changes, explain the interruption and obtain confirmation before stopping and restarting. Cancellation changes neither selection nor running state. If stopping fails, do not launch the next server.
- Servers continue after SwiftBar exits, and the same self-launched servers remain manageable after restart. Do not automatically start at OS login or restart after abnormal server termination. Do not change the engines' own recovery or idle-unload behavior.
- Externally launched servers are monitoring-only. Do not stop, take ownership of, or switch their models. Treat Splash running in the parent Herdr pane during initial validation as external too; do not stop it without permission.
- Store user configuration in `config/local-llm-server.json`. Exclude `config/*.json` from Git and track only `config/*.example.json`. Do not put specific models or personal paths into the implementation or tracked configuration examples.
- For Strata, register a display name and a prepared model configuration JSON, and use that JSON directly. Do not handle overrides such as expert cache, model downloads, initial preparation, or deletion.
- For Splash, register a display name, model ID, and CLI argument array `args`. Pass optional shared `modelCacheDir` as `HF_HUB_CACHE`. When omitted, do not override the location or move existing files.
- For Splash normal startup and running-model switching, let Splash download missing models or required drafts. The user registers models by editing JSON, and the menu reflects them on the next refresh. Selection while stopped does not download or start anything. Retain Strata's references to prepared configuration JSON (additional user-approved specification).
- Disable Open chat while the server is stopped. It remains available during idle unloading because the server is running. Even an action from a stale menu after stopping must not open the browser if the endpoint is stopped.
- Restrict both engines to `127.0.0.1`. Configure ports separately, defaulting to Strata 8080 and Splash 8000. Identical ports are a configuration error.
- Fixed UI text (menus, confirmation dialogs, validation errors, and missing-dependency guidance) is English. Do not translate user-specified model display names (additional user request after implementation).
- The persistent display is icon-only. Distinguish states with shapes and marks, not color alone. The open menu shows each engine's state, model, endpoint, actions, chat/log/configuration links, generation speed, engine-only memory, and context limit.
- Refresh status every 5 seconds. Generation speed is based on the current observation window; do not present a cumulative average as current speed. Use `—` when unavailable or not generating.
- Memory is **the physical footprint of the native inference engine alone, equivalent to Activity Monitor's “Memory” column**. Do not add the Python API server or other processes, or substitute Metal allocation, RSS, or system-wide RAM. Use `—` when unavailable.

## Implementation Decisions

### Structure and runtime

- Use `local-llm-server.5s.sh` as the entry point, relatively linked from `enabled/` at the repository root. Handle display and click actions through the same entry point; keep helper code in the plugin's `scripts/`. Have SwiftBar scan only `enabled/`.
- Use the Python 3.12+ standard library. Handle JSON, HTTP, file locks, processes, Unix sockets, and macOS API calls without adding external Python packages or a Swift build step.
- The entry point finds `uv` in PATH and known Homebrew locations and launches helpers with `uv run --offline --no-project --no-python-downloads --python '>=3.12'`. Prepare the required Python during installation; do not install or fetch over the network during periodic refresh. Launch workers with the resolved `sys.executable`.
- Resolve the repository location independently of the working directory. Do not assume SwiftBar's launch PATH matches the terminal PATH. Return an error icon and guidance even when dependencies are missing.
- Separate configuration loading, engine-specific startup/HTTP monitoring, process management, macOS measurement, and menu rendering. Keep the initial implementation within this plugin; do not preemptively build a general API for other plugins.
- New documentation and comments are in English. Comments explain reasons only.

### Configuration and local state

Configuration schema outline (values are illustrative, not initial model defaults to write during installation):

```json
{
  "strata": {
    "directory": "/path/to/Strata",
    "port": 8080,
    "models": [{"id": "local-model", "name": "Display name", "config": "/path/to/model.json"}]
  },
  "splash": {
    "executable": "/path/to/splash",
    "port": 8000,
    "modelCacheDir": "/path/to/huggingface/hub",
    "models": [{"id": "local-model", "name": "Display name", "model": "owner/repository:VARIANT", "args": []}]
  }
}
```

- `strata` and `splash` may each be omitted. Display an unconfigured engine as unconfigured; a problem with one engine's models or runtime must not make the other unusable. Tracked examples have empty model lists and no real paths.
- Model `id` is a stable key unique within the engine, restricted to a safe character set. Do not use display names or array positions as state identifiers. Store and display the selected and running models separately. If none is selected, explicitly prompt for model selection.
- `splash.executable` is optional. If omitted, resolve the executable from PATH/Homebrew. Resolve Python and server.py from `strata.directory`. Allow absolute paths or `~/`; reject relative paths.
- Pass `args` to the process as a string array without shell evaluation. Reject managed items `--model`, `--host`, `--port`, `--offline`, control-changing options such as `--help`, and the `--` separator. Validate `--key=value` forms and abbreviations accepted by Splash too, so managed values cannot be overridden indirectly.
- Validate types, empty values, duplicate IDs, port ranges, NUL, and configuration syntax. Escape menu control characters and newlines in display names; pass validated internal IDs, not display names or raw model IDs, as click arguments.
- The plugin does not rewrite user configuration. Even if editing removes a model or breaks configuration, Stop and log access for self-launched servers remain available from launch-time state.
- Keep persistent state in `~/Library/Application Support/swiftbar-plugins/llm/` and plugin launch logs in `~/Library/Logs/swiftbar-plugins/llm/`. Do not store model weights, secrets, complete environment variables, or conversation text in state or the repository. Rotate logs per launch with a size limit.
- Copying the configuration example is a manual initial-installation step; do not overwrite existing configuration. Do not automatically register or start models on first use.

### Server ownership and operations

For safe persistent management, use **one small worker per running server**. This is not an autostart service: it owns the server from Start to Stop and does not restart it automatically.

- The worker becomes leader of a new session/process group detached from SwiftBar and launches the target server as a child in that group. Detach stdin from the terminal and explicitly connect stdout/stderr to logs. Keep the worker alive until the group is empty to prevent PGID reuse.
- Send operations to the worker through a user-private Unix socket. Put the socket in a private temporary directory with a short path and verify length limits. Persist a per-launch nonce, worker PID/start time, boot identity, and endpoint. Validate responses against the nonce too.
- Use per-engine file locks and worker-side serialization to prevent races among repeated clicks, periodic refresh, and concurrent clicks. Do not impose mutual exclusion between Strata and Splash.
- Verify the worker is currently the group leader before sending stop signals. The worker continues shutdown rather than exiting immediately on a signal. Normally request graceful server shutdown with SIGTERM and terminate remaining descendants in the same group too. If they do not exit within a fixed interval, retain ownership, report stop failure, and refuse restart. Do not implicitly force KILL or directly kill saved PIDs/PGIDs.
- For both normal stops and abnormal exits, record termination only after checking for surviving descendants. If the worker itself is lost, do not adopt processes from old records and resume control. Report them as external/ownership unknown, and check liveness and ports before a new launch.
- Do not infer ownership from ports or process names. An HTTP-returned PID is not grounds for stopping either. Insufficient process-inspection permission means “unknown,” not “exited.”
- The worker retains a snapshot of the launch-time model, port, and executable path. Configuration changes must not hide an old server or cause a duplicate launch on another port.
- Startup is asynchronous so downloads/model loading do not block SwiftBar refresh. Do not automatically stop merely because the API is unresponsive. Confirm Stop during startup every time too.
- Implement confirmation using `osascript`, passing text as arguments to fixed AppleScript; do not embed user values into AppleScript source. Do not change running state or selection while awaiting confirmation; revalidate configuration and worker generation after approval. Combine stopping for a model change into one confirmation.
- Selecting a model while stopped only saves the selection. While running, save the selection and launch only after approval and completed stopping. If startup fails, retain an error and do not automatically restart the previous model.

### Engine-specific launch contracts

**Strata**

- `<directory>/.venv/bin/python <directory>/serve/server.py --engine strata --config <registered-config> --host 127.0.0.1 --port <port>`. The working directory is the Strata root.
- Reference configuration JSON directly; do not generate a copy or override `args` or `env`. Explicitly set CLI host/port for connection management.
- Resolve the expected native-engine path from JSON `exe` and `cwd`, and use it to identify the actual child process. Do not guess memory when the configuration is ambiguous or has multiple candidates.
- Explain missing initial preparation through guidance to Strata's existing tools and logs; do not automatically run setup. Engine logs follow `log` in the referenced JSON, so distinguish them from the plugin's server logs.
- Strata itself may write Web settings and other data to the original JSON or adjacent files. The plugin itself does not modify them, but do not imply that normal Strata behavior becomes read-only.

**Splash**

- Use the official `splash serve --model <ID> --host 127.0.0.1 --port <port> ...args`. Do not depend on internal Python module invocation formats.
- Do not add `--offline` when launching Splash, and remove `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` from the child's environment. Do not change the parent environment. Override the model cache only when specified.
- The 1.3.2 launcher execs into the API server after preparation. Expect the executable for the same PID to change; do not measure the Python API server as engine memory.
- Identify the native engine by descendants, executable, and the `serve-native` role. Re-resolve after PID changes caused by internal restart and reset the speed-observation baseline too.
- Do not unilaterally disable authenticated API support. If authentication is required and monitoring values cannot be obtained, display “Monitoring unavailable” and `—`. Do not add credential management in this work.

### Status collection, memory, and menu

- Identify Strata by `service == strata` in `/health`, and obtain `loaded` and `max_context`. Use `/metrics` values `live.state`, `live.tok_s`, and `engine.max_context`. Do not persist request history in responses.
- Validate Splash's `/status` schema, instance, ready, and other fields. Compute generation speed from differences in `metrics.decode_output_tokens` and a monotonic clock; invalidate on instance changes, counter rollback, after sleep, and on first observation. Do not substitute cumulative GPU speed or Metal memory.
- Apply short HTTP timeouts and response-size limits; do not let failures affect refresh of the other engine. Do not misclassify 401, timeouts, invalid JSON, or another service as Stopped. Do not follow redirects to external hosts.
- Distinguish startup with no API response, running server/model unloaded, externally running, stop failure, and invalid configuration. Idle unloading is not server shutdown.
- Aggregate icon priority is error → starting/stopping → any running → all stopped. Show details in separate Strata/Splash submenus.
- Use `ctypes` to call libSystem's `proc_pid_rusage(pid, RUSAGE_INFO_V0, ...)` and obtain the current `ri_phys_footprint`. Define the V0 structure exactly as declared in the Apple SDK; verify its size is 96 bytes and the field offset is 72. Validate target identity before and after reading using `ri_proc_start_abstime` and other fields.
- Identify self-launched engines under the worker. Measure external servers only if their engine PID can be safely identified through read-only inspection; otherwise use `—`. Discovering an external PID grants no management authority.
- Label it “Engine memory” and make the PID inspectable too. Display GB (decimal); for measured comparisons align raw bytes, display units, and sample times. Do not add API servers, separate draft processes, vision, or other processes.
- Pass actions to the entry point through SwiftBar's `bash`, `paramN`, and `terminal=false`. Safely handle menu control characters, quotes, and spaces. Do not wait for slow startup completion in click handling. Do not relaunch from notifications or UI updates.
