# SwiftBar plugins

macOSのメニューバーから使うプラグイン集です。`Local LLM`はStrataとSplashの状態表示、起動・停止、モデル選択を1つのメニューにまとめます。

## 導入

macOS、[SwiftBar](https://github.com/swiftbar/SwiftBar)、`uv`、Python 3.12以上が必要です。Homebrewを使う場合は次を実行します。

```fish
brew install uv
brew install --cask swiftbar
uv python install 3.12
```

このリポジトリを配置したディレクトリで、設定例をコピーします。`cp -n`は既存の設定を上書きしません。

```fish
mkdir -p ~/.config/swiftbar-plugins
cp -n examples/llm.json ~/.config/swiftbar-plugins/llm.json
```

SwiftBarのプラグインフォルダに、このリポジトリの`plugins/`を指定してください。既存のフォルダを使っている場合は、ほかのプラグインを保全してから変更してください。補助コードを含むリポジトリ全体をプラグインフォルダには指定しません。

入口は`plugins/llm.5s.sh`です。配置パスには改行・制御文字・`|`を含めないでください。定期更新ではPythonやモデルをダウンロードしません。依存不足のアイコンが出た場合は、先に上記の導入を完了してください。

## モデル設定

`~/.config/swiftbar-plugins/llm.json`を編集します。モデルは自動登録されません。設定例のモデル一覧は空です。`strata`・`splash`は片方だけでも使えます。

各エンジンの`models`配列に、次の項目を持つオブジェクトを追加します。

| 項目 | Strata | Splash |
|---|---|---|
| `id` | エンジン内で一意のID。英数字、`-`、`_`。先頭は英数字、64文字以内 | 同左 |
| `name` | メニューに表示する名前 | 同左 |
| `config` | 準備済みのStrata設定JSONの絶対パス | 不要 |
| `model` | 不要 | Splashに渡すHugging FaceモデルID |
| `args` | 不要 | モデルごとのCLI引数の文字列配列。省略時は空 |

エンジン共通の設定は次のとおりです。

| 項目 | 内容 |
|---|---|
| `strata.directory` | Strataのインストール先。`.venv/bin/python`と`serve/server.py`が必要 |
| `strata.port` | 既定8080 |
| `splash.executable` | `splash`実行ファイルのパス。省略時はPATHとHomebrewの標準配置から探索 |
| `splash.port` | 既定8000 |
| `splash.modelCacheDir` | 任意。指定すると子の`HF_HUB_CACHE`へ渡す。省略時は既存の保存先を使用 |

パスは絶対パスまたは`~/`で指定します。両エンジンに同じポートは設定できません。接続先は`127.0.0.1`に固定しています。

Splashの`args`は、引数と値を別の文字列にしてください。シェル展開は行いません。`--model`、`--host`、`--port`、`--offline`、ヘルプ等の制御オプションとその省略形は指定できません。認証を有効にしたサーバーは起動できますが、認証が必要な監視APIの値は取得できません。

Strataの元JSONを直接使います。expert cacheなどはそのJSONで設定し、モデルの取得・初回準備はStrataの既存手段で行ってください。Strata Menubarの設定は同期しません。プラグインは元JSONを書き換えませんが、Strata自身のWeb設定操作等は元ファイルや隣接ファイルへ書き込むことがあります。

## メニュー操作

停止中にモデルを選んでも起動しません。モデルを選んで「起動」を押します。StrataとSplashは独立して起動できるため、メモリの余裕を確認して操作してください。

- **停止**は毎回確認します。処理中のリクエストも中断します。
- **稼働中のモデル変更**は確認後に停止・再起動します。キャンセル時は選択もサーバーも変えません。停止に失敗したら次を起動しません。
- **Splashの通常起動・モデル変更**はオフラインです。未取得モデルで失敗した場合は、ログを確認し「ダウンロード／更新して起動」を使ってください。オンライン操作でも取得完了をメニュー処理で待ちません。
- **外部で起動したサーバー**は監視のみです。停止・取り込み・モデル変更は行いません。

Strata Menubarから切り替えるときは、そちらでサーバーを停止してアプリを終了してください。ターミナル等で起動したサーバーも元の手段で停止し、ポートが空いてからSwiftBarで起動します。

SwiftBarを終了しても管理中のサーバーは継続します。再びSwiftBarを開くと操作を再開できます。ログイン時のサーバー自動起動や、異常終了後の自動再起動は行いません。

## 表示とログ

5秒ごとに更新します。アイコンはエラー、処理中、稼働、全停止を形で区別し、詳細は各エンジンのサブメニューに表示します。

- **生成速度**: StrataはAPIの移動窓、Splashは直近の出力トークン増分と経過時間。非生成時、初回、再起動、スリープ後など有効な観測がないときは`—`。
- **エンジンメモリ**: ネイティブ推論エンジン単体のphysical footprintを10進GBで表示。アクティビティモニタの「メモリ」と同じ指標です。APIサーバー分は合算しません。特定・取得できなければ`—`とし、RSSやMetal値では代用しません。実エンジンとActivity Monitorの実測照合はまだ完了していません。
- **モデル未ロード**: アイドル解放した状態です。サーバー自体の停止とは区別します。
- **監視不可**: 認証、タイムアウト、応答形式の不一致など。サーバー停止とは判断しません。

プラグインのサーバーログは`~/Library/Logs/swiftbar-plugins/llm/`、所有権・選択などの状態は`~/Library/Application Support/swiftbar-plugins/llm/`へ保存します。ログは1ファイル1MiB、バックアップ2本を上限に、起動時と容量到達時にローテートします。Strataエンジン自身のログは、登録したJSONの`log`も確認してください。

設定を壊したりモデル登録を削除した場合も、管理中サーバーの停止とログ参照は残ります。workerが失われて「所有権不明」になった場合は古いPIDを使って停止しません。起動元のログやアクティビティモニタで手動確認してください。サーバーが残っている間は状態ファイルを削除しないでください。

検証コマンドと実機の確認状況は[実装計画](docs/plans/2026-10-19-llm-menu.md)を参照してください。
